## 优先解决的工程问题

### 1. 无稀有度端到端

清理 `CardDef/Rarity`、抽卡卡种权重、制作 / 回收费、商店人口稀有档、招募 / 出售价、市场筛选、UI 角标、后台和测试。新规则价函数只接受品质。旧 `cost` 是历史算分行动消耗，不得当隐藏基价。

只允许 legacy 读取器 / 进行中旧对局使用冻结旧映射，列出 allowlist。删除 `CardDef.rarity` 后不能让旧局售卡访问不存在的字段。

### 2. 抽卡不是简单把按钮改名

新增持久单抽订单：begin 扣费并存三候选、预留一格 → pending 可恢复 → claim 原子发一张。每用户最多一份待选；没有取消退款重抽或超时换候选。候选不是库存卡。

同 requestId begin 重试同结果；同订单重复 claim 即使用不同 requestId 也最多发一张；异候选二次领取拒绝。跨用户、伪造品质 / 费用 / 来源拒绝。十连扣费、十卡、来源、流水和回放一次事务，不允许半包成功。

所有发卡及撤单 / 收礼都考虑待选容量预留和托管返还，不因新抽满库丢挂单卡。动画不决定到账。

### 3. 单星币与来源闭环

只有一个可写星币总额，不维护两份真余额。来源子额度不单独设币名 / 图标 / 兑换。本人消费显式支付策略；市场只用普通额度。抽卡、制作、成功合成、分解及再制作全链继承；客户端不能传 free 标签决定权限。

普通卡混受限材料 / 费用成功后自用，要确认；失败主卡原权限不变，返还同 UID 同来源。十连混付初版整包自用，支付前说明。保留正常游玩产物自由交易。

### 4. 礼包、奖励与对账

`ensureProfile` 不再先发旧礼包；profile 层提供 pending/claimed/legacy_granted，一用户只能领取一次，各登录提供方共享这层服务。新手并发选卡不重复发放。

对局奖励按版本固定，老局别回溯套新参与条件。不要把自动离线完成等同于真人有效游玩。统计 faucet/sink/transfer/migration，玩家交易额不是回收，分解返币也是发行；托管卡计库存，候选不计库存。

### 5. 迁移及旧对局

保留 user、defId、uid、rank、成交记录、老 requestId 回放。星尘 / 券迁移幂等，先 dry-run，资产来源不明不擅自降权。活跃挂单也迁元数据，保留挂牌费用规则，历史手续费读真实值。

进行中旧局按冻结规则结束，新局才用统一品质价；单位保存出售 basis，合星累加，避免低买高卖。回滚需考虑新订单和来源余额，不能只 revert 代码或丢弃切换后资产。
