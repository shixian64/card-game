## 用户已确认的方向

- 游戏是短局，只需要每房间两名真实玩家互相对战，不做八人局，也不是双人合作打电脑。

## 工程上必须做到

### A. 真正双边输入，一份结果

现 `matches(user_id)` 是单人局，不能保存两条独立局就称双人。新房间有两参与者，同round/phase/deadline。

现 createBattle 的测试enemyTeam也不足：必须支持对方完整阵容、站位、品质、星级、装备，输出唯一 A/B/draw 结果和统一回放。双方客户端只做视角转换；B不是自己再跑一次模拟。

六边形映射走现 hex.ts，验证180°旋转保持邻接 / 距离；注意旧slotToCell的enemy映射只翻行不翻列，重构后的主对局必须新适配，不能污染旧回放；临时unitId加房间与归属命名空间，不能两人c1碰撞。同速与超时不能固定偏向A或守方。

### B. 同步屏障与幂等

短事务冻结两人输入、处理免费装备选择到期、存inputHash/seed → 事务外模拟 → 条件更新存结果 → 同deadline原子应用双方生命 / 金币 / 野怪 → 终局双方永久奖励一次。

进程在任何阶段崩溃可从同输入恢复，不重新roll。server timer推进，不依赖浏览器轮询。SQLite是单writer，不能长写锁包住整段战斗模拟。

命令校验phaseId+本人playerRevision，不用全局revision卡住另一个人买卡。成功requestId重试回原结果，不能换id自动重复扣款。

### C. 金币、basis与回收

免费单位basis0，付费为实际成交价；合星sum basis，出售退basis。金币不变永久星币。对局不发未来无用收入。

人口自动，XP动作在重构后的主对局拒绝。商店买一格不自动补一格。固定每卡品质与8种牌组只影响本局，不改永久抽卡概率或发新永久卡。

### D. 装备必须参与战斗

六原型见详细表：攻击、技能系数、HP/护甲、一次性开局护盾、普攻回能、每三普攻附加伤害。当前speed只是先手顺序，不能加speed就宣称攻速提升。

区分basic/skill/item伤害上下文，技能双射不计两次普攻；额外伤害不触发自身、不回能，护盾不每帧刷新。引用原itemId，穿戴 / 卸下 / 售卡 / 合星都不能复制或丢物。

组件配方仅预留结构，首版不用做几十件装备、碎片或额外货币。

### E. 隐私、断线与奖励

对方当前站位修改、商店、背包、选装订单不发给自己，侦察只上轮已公开阵容。不是完整返回后前端hide。

断线不暂停，保留阵容，宽限可重连；服务重启不是玩家弃权。长期整站中断明确abort，不离线补一整场假PvP。投降与终局一次结算，双方奖励 / pair / 个人配额 / ledger / active lock同事务。

邀请房可拿有上限的奖励，不要求陌生人匹配，否则只有两个活跃用户时无法养成；但不能无限互刷。

### F. 兼容既有工作

旧v1/v2/v3单人局仅作存续兼容，冻结结束；切换后停旧单人开局，主对战入口直接进入双人房间。duel独立规则是版本隔离，不是另做一个模式。不得全局改价格 / 星级把旧局买卖和回放污染。新旧正式局共用活跃占用 / 奖励配额。

保留现有单星币、抽卡、来源、新手礼包及LINUX DO代码；共享入口先看最新diff，小范围集成，不覆盖并行修改，不自动跑旧余额换算。
