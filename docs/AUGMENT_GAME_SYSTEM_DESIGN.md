# 星序 ASTERIA｜「星契」玩法设计与实现（借鉴金铲铲 / TFT 海克斯强化）

> 版本：DUEL-RULES-2，2026-10-18（Asia/Shanghai）。
> 状态：**代码、服务端与静态 UI 已实现，`npm test` 685/685 通过；未执行构建，未做浏览器实机验收。**
> 本文不是“已平衡”声明。所有数值均为起测默认值，未经用户最终确认；不能把测试通过当作胜率验证。

## 1. 本轮要解决的问题

双人短局已经有商店、利息、合星、站位、装备和羁绊，但每局开局几乎一样：

- 8 个卡种 + 固定品质由赛前决定，局内变化主要来自商店随机；
- 玩家在同一套经济曲线里做同样的“买 / 刷 / 存”；
- 缺少一类**每局不同、能改变打法**的长期增益，也缺少“围绕它做取舍”的构筑身份。

金铲铲 / 云顶之弈的**海克斯强化（Augment）**正好回答这个问题：不增加新美术、新货币或新卡池，只给每局三次三选一，就能让同一套卡打出不同节奏。本轮把它改造成原创的「星契」。

## 2. 从金铲铲 / TFT 学到的四件事

以下是对公开规则结构的概括，不是对原作当前赛季全部细节的复述；本项目没有读取或复用原作客户端数据。

| 学到的点 | 原作大致做法 | 本项目的改造 |
| --- | --- | --- |
| 固定时点、有限次数 | 一局通常三次强化，分布在 2-1 / 3-2 / 4-2 | R2 / R5 / R8 各一次，正好在三次野怪之后 |
| 三选一、分档 | 每次三选一，银 / 金 / 彩三档 | 微光 / 星辉 / 星冕三档，每档 6–8 张 |
| 强化改变打法 | 经济、商店、战斗、羁绊、装备、节奏 | 六类效果，全部走现有系统，不新增资源 |
| 信息与侦察 | 对手已选强化可见 | 双方候选相同、已选对对手公开、待选候选不泄露 |

值得强调的是：**强化不是“多给一点数值”**。如果三张候选都只是 +5% 攻击，玩家只会选最大数；真正有价值的是“这一局我围绕经济、某个羁绊或某件装备来打”。

## 3. 为什么没有照搬

- **不做八人房 / 共享卡池 / 选秀抢装**：当前主玩法是两人房，强塞八人结构会破坏既有房间、计时和奖励边界。
- **不做英雄强化**：英雄强化绑定具体棋子，会放大“抽到某张卡才能玩”的问题，与“所有卡种同品质同价”的既有决定冲突。
- **不做强化重掷**：首版保持三选一决策清晰；重掷会额外增加一次随机与节奏操作，留待后续单变量实验。
- **不做付费 / 永久强化**：星契只在本局生效，不进收藏、不进市场、不换星币，避免把对局强度变成账号资产。
- **候选双方相同**：1v1 不是八人混战，公开同集更公平，也方便复盘；代价是双方可能拿同一张，这是有意为之。

## 4. 规则

### 4.1 时点与流程

| 轮次 | 类型 | 星契档位 | 说明 |
| --- | --- | --- | --- |
| R1 | 野怪 | — | 基础补给与第一件装备 |
| **R2** | PvP | **微光星契** | 第一次三选一，建立本局方向 |
| R5 | PvP | **星辉星契** | 中期补强，围绕已有方向加码 |
| **R8** | 野怪 | **星冕星契** | 末段大招，决定 R9–R10 的胜负手 |

- 每次从本档随机抽 **3 张不同**星契，双方候选集合相同；
- 每名玩家独立选择，最多持有 3 张（每档 1 张）；
- 选择窗口是该轮备战阶段；**未选不会卡住对局**，备战截止时按候选顺序自动选第一张；
- 已选星契对对手公开；未选候选不进入对手视图；
- 星契状态存在参与者 JSON 中，随房间快照持久化；不新增表，不需要迁移旧房间；
- 旧存续房间（rules_version=1）不生成星契，仍按 v1 结算。

### 4.2 效果层与结算顺序

战斗内统一顺序：

```text
基础职业 → 品质 → 局内星级 → 装备（同类百分比先相加，受装备强化倍率）
→ 星契（同类百分比先相加）→ 羁绊（含星契徽记 +1）→ 一次性护盾
```

- 星契的百分比与装备百分比**不在同一层相加**，避免“装备精通”把星契也放大；
- 装备 + 星契的开局护盾合计上限为最终生命 25%（月系羁绊护盾不在此上限内）；
- 伤害仍只有 `basic / skill / item / neutral` 四种上下文，不新增伤害类型；
- 星契不改变攻击频率、射程、控制时长或目标数。

## 6. 经济影响（起测估算）

不是实际对局收益，只是量级检查：

| 星契 | 最粗估值 | 备注 |
| --- | --- | --- |
| 私房钱袋 | +24 金 | R3–R10 共 8 轮 ×3 |
| 黄金时代 | +16 金 + 利息 | R9–R10 共 2 轮 ×8；利息另算 |
| 免费重掷 | 30 金等价 | 3 次 ×10，可跨轮保留 |
| 升星赏金 | 约 +24 金 | 假设 4 次合星（1 次三合一 + 3 次三合二） |
| 战利品风暴 | 立即 1 件装备 + R8 野怪金币 24→48 | 若 R8 选到，正好赶上该轮野怪结算 |
| 加宽货架 | 每次刷新多看 1 格 | 价值取决于刷新次数与目标卡 |

与十轮保底 286 金相比，这些强化是“方向性”的，不会直接跳过买卡 / 刷新 / 合星的基础预算。数值仍需真实对局校准。

## 7. 公平性边界

- **同候选**：双方看到同样的三张，避免“A 刷到经济、B 刷到战斗”的纯随机差；
- **公开已选**：对手能看到你选了哪张，便于针对性站位 / 转型；
- **装备候选的例外**：`战利品风暴` 只让持有者多一个装备候选；这是强化收益，基础三候选仍对双方相同，未持有者不减少；
- **无永久资产**：星契不进收藏、市场、奖励结算；终局全部清零；
- **不改变奖励**：胜 / 负 / 平 120 / 100 / 110 星币与配额不变；
- **规则版本隔离**：新房间 `rules_version=2`；旧 v1 房间不生成星契，仍按 v1 结算；
- **测试隔离开关**：`createDuelService({ augmentsEnabled:false })` 只用于既有全量回归的固定基线；生产默认开启，不是面向玩家的模式选择。

## 8. UI

- **星契三选一面板**：出现在备战侧栏顶部，显示档位、类别、名称与完整效果；未选时提示“本阶段结束前未选将按候选顺序自动选第一项”。
- **星契条**：HUD 下方显示我方 / 对方已选星契，按档位着色；悬停显示效果。
- **羁绊面板**：本轮新增，复用战斗内核 `getSynergies`，按不同卡种计数，显示 `count/threshold` 与激活状态；星契徽记会追加计数。此前对局页没有羁绊进度，这是可玩性上的明显缺口。
- **动态商店**：显示实际格数（5/6）、刷新价（10/8/0）与剩余免费次数；人口提示包含第六席加成。

## 9. 镜像公平修复（本轮顺带发现）

用星契做镜像体检时发现一个**既有的严重问题**：某些远程顺序下，同一镜像阵容 A 方 200 局全败、B 方全胜。原因不是星契，而是走位平局规则最后按物理列号 `a.col - b.col` 排序；B 方经过 180° 旋转后，这个平局方向被固定反转，形成系统性偏置。

修复：

- 新增 `laneCol(side, col)`：B 方先把物理列镜像回本地列，再做平局比较；
- 只改走位 / 闪现的**平局次序**，不改距离、射程、伤害或技能；
- 通过 `rulesVersion >= 2` 启用，v1 黄金回放与旧房间完全不变；
- 回归用例 `B05b`：换序镜像 200 种子，修复前 A=0 / B=200，修复后 A=100 / B=100。

这是本轮除星契外最重要的玩法修复：玩家不应该因为坐在 A/B 座而输。
